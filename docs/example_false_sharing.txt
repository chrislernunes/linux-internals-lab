  ratio mean(same line) / mean(64B pad) = 6.03315
  ratio mean(64B pad) / mean(128B pad) = 0.965513  (above ~1 suggests adjacent-line prefetch coupling)

why:
  A cache line (64 bytes on this x86) is the unit of coherence, not
  the variable. Two cores cannot both hold the same line in Modified.
  Each fetch_add needs the line Exclusive/Modified, which invalidates
  the other core. That is a read-for-ownership (RFO) per increment,
  even though the threads never touch each other's counter and even
  though the memory order is relaxed. On x86 the RMW is a lock-prefixed
  instruction regardless of memory_order_relaxed.
  Padding to 64 bytes gives each core its own line, so the increment
  hits in L1. Padding to 128 bytes also steps past Intel's adjacent-line
  prefetcher, which otherwise pulls the neighbour and can re-couple two
  'nicely padded' counters. If the 64B and 128B results match, the
  prefetcher is not the bottleneck on this CPU today; the 64B result
  is still the one to ship in a struct-of-counters.
  Verify, do not trust the story alone:
    perf stat -e cache-misses,LLC-loads,LLC-load-misses,cycles,instructions \
      taskset -c 0,1 ./build/linuxlab false-sharing
  The same-line case should show a miss storm with almost the same
  instruction count. If both look identical, the threads were not
  actually running on two cores (check /proc/self/status Cpus_allowed
  and that you have two online CPUs).
